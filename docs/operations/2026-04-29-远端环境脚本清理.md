## 2. 原始需求

- 用户原始诉求：当前项目有很多 ps1 脚本，删除多余的脚本，都使用 35.208.147.180，而不再使用本地 ip。
- 原始上下文：项目刚完成环境迁移，上一轮检查发现 home/office 脚本和环境配置不一致，存在启动风险。
- 后续补充：无。

## 3. 摘要

本需求将开发启动入口收敛为远端环境，删除项目内 PowerShell 启动脚本，并把环境示例和 Spring 默认配置统一指向 `35.208.147.180`。

## 4. 背景和目标

- 业务背景：迁移后不再需要在本地 IP 与 office IP 之间切换，启动脚本过多会增加误用概率。
- 用户 / 问题陈述：现有脚本仍包含旧本地基础设施地址和 home/office 切换语义。
- 目标：删除 PowerShell 启动入口，并让默认配置使用 `35.208.147.180`。
- 成功标准：项目内 ps1 启动脚本删除；配置示例不再引导使用本地基础设施地址；验证命令通过或明确记录未验证项。

## 5. 范围边界

### 本次做

- 删除根目录环境切换脚本、各服务 `dev.ps1` / `dev_office.ps1` 启动脚本，以及调用已删除 ps1 的无效 bat 包装脚本。
- 修改环境示例、Spring profile/default 配置和前端 API 示例，统一使用 `35.208.147.180`。
- 更新相关文档中的启动命令说明。

### 本次不做

- 不修改真实 `.env` 秘钥内容。
- 不调整业务代码、数据库结构、API 行为。
- 不安装 Docker、Node 依赖或启动长驻服务。

### 假设

- “本地 ip”包括旧 home 地址以及基础设施连接里的本机示例地址。
- 浏览器开发服务仍可监听 `0.0.0.0`，本次重点是后端依赖和服务 API 目标地址。
- 不再保留 PowerShell 启动入口；服务启动使用原生命令。

### 待确认问题

- 无。

## 8. 实施方案

- 方案概述：删除 home/office 分流脚本和服务级 PowerShell 启动脚本，配置默认值直接使用远端环境。
- 关键设计决定：不再保留 `UseLocalInfra` 或服务级 `dev.ps1` 参数，避免脚本继续提供本地基础设施入口。
- 替代方案与取舍：也可以保留 `switch-env.ps1` 但只允许 office；这会留下无价值的切换层，因此不采用。
- 风险：真实 `.env` 未修改，若本机仍保留旧 `.env`，直接启动时可能受本地文件影响。

## 2. 原始需求

- 用户原始诉求：补齐检查报告相关能力，尤其是各种彩超；先从需求出发，不考虑代码实现。
- 原始上下文：系统已有检验报告结构化解析、指标联动、趋势和 Agent 分析；检查报告目前主要作为普通记录和影像分类存在。
- 后续补充：首期只做彩超/超声报告文本，不做图像分析；面向患者本人；优先支持单份解读和多次报告随访；默认最新对上次并给近几次总览；结论引用报告原文；动作建议用分级建议。
- 2026-05-09 产品反馈升级：当前“无法判断”过粗，缺少患者最关心的“危险吗、比上次差了吗、下一步做什么”；需要结构化趋势表、缺失/阴性/显示不清区分、证据等级、关键指标缺失提醒，并将肝硬化相关风险联动到全局病程能力。

## 3. 摘要

本需求已为超声/彩超文本报告新增报告级解读与随访能力。升级阶段将在保持旧字段兼容的基础上，把彩超结果从“报告文字对比”提升为“结构化病程线索”：展示局部趋势、缺失信息、检查局限性、肝硬化相关风险模块和复诊问题清单，并将新结构注入 Agent 上下文。

## 4. 背景和目标

- 业务背景：检验报告有数值指标和规则分析，而彩超等检查报告更依赖文本结论、所见和复查建议。用户需要理解“这次报告是什么意思”以及“和上次相比有没有变化”。
- 用户 / 问题陈述：患者看到多份彩超报告时，难以快速判断本次是否比上次变化、是否需要复查或就医。
- 目标：在不做图像识别和病灶级追踪的前提下，提供患者可理解的报告级解读、随访变化摘要、原文依据、分级动作建议、结构化趋势表、关键缺失项和复诊准备清单。
- 成功标准：详情页和 Agent 均可消费升级后的超声/彩超随访结果；单份报告不伪造趋势；多份报告展示最新对上次；非超声报告不触发；肝硬化/慢性肝病彩超能突出局部稳定、不确定项和需补充信息。

## 5. 范围边界

### 本次做

- 自动识别超声/彩超类文本报告。
- 在记录详情响应中新增超声/彩超随访结果。
- 单份报告展示本次解读、证据和动作建议。
- 多份报告展示最新对上次的报告级变化和近几次摘要。
- Agent 报告分析上下文携带超声/彩超随访结果，并更新提示词优先引用该结果。
- 前端报告详情页展示超声/彩超随访卡片。
- 结构化展示彩超发现模块，区分“存在、未见、未提及、显示不清、未检查、可疑异常”。
- 对肝硬化/慢性肝病相关肝胆彩超，输出肝癌筛查完整性、门静脉高压线索、失代偿警讯三个风险模块。
- 输出关键指标缺失提醒和复诊问题清单，复用现有检验趋势、症状和风险模块作为全局病程能力。
- `/agent` 疾病总览展示最新彩超病程摘要，让能力不只停留在单份报告详情页。

### 本次不做

- 不做彩超图像分析。
- 不做病灶级精准匹配。
- 不覆盖 CT、MRI、X 光、心电图、内镜等其他检查类型。
- 不新增数据库表或持久化随访结论。
- 不给出确定诊断或治疗方案。
- 不把所有彩超病种一次性做成完整专病风险模块；本次优先做肝胆彩超/肝硬化场景，其他彩超保留通用解读。

### 假设

- 当前解析结果中至少能提取超声报告的关键所见、提示、结论或证据片段。
- 首期使用报告标题、分类和解析文本中的关键词识别超声/彩超报告。
- 分级动作建议是患者提示，不替代医生判断。

## 8. 实施方案

- 方案概述：Java 端从当前记录及同疾病档案历史记录中派生超声/彩超随访结果；升级后继续派生但输出结构化发现表、风险模块、缺失信息和复诊问题；前端优先展示结构化结果；Agent 生成提示词将其作为可信上下文引用。
- 关键设计决定：不建新表，不持久化随访结论；保留旧字段兼容；肝胆彩超/肝硬化场景先做确定性规则；“未提及”不当作阴性，“显示不清”降低可信度；无法判断整体好坏时仍输出可判断的局部趋势。
- 替代方案与取舍：直接调用 LLM 生成随访结论表达更自然，但会增加外部调用、缓存和幂等复杂度；首期先做确定性派生，LLM 只负责自然语言解释。
- 风险：关键词判断不能替代医学审核，报告文本抽取质量会影响随访结果。

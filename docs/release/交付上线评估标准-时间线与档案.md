# 交付上线评估标准-时间线与档案

## 评估结论规则

| 结论 | 判定规则 |
|------|----------|
| PASS | 档案选择、时间线排序、批次详情和导航上下文均通过。 |
| CONDITIONAL | 主链路通过，部分展示或空状态存在限制。 |
| FAIL | 时间线顺序错误、批次详情缺失，或导航丢失上下文。 |

## 业务范围

范围内：疾病档案、记录时间线、批次详情聚合、记录详情导航、趋势面板。

范围外：复杂跨疾病合并、医生端病历视图。

## 自动化测试

建议命令：

```powershell
pytest tests/contract/test_timeline_endpoints.py tests/integration/test_us3_timeline_order.py
```

通过标准：接口和排序集成测试通过。

失败处理：标记 `FAIL`；若仅空状态缺失，记录为 P2 缺口。

## 手工验收

操作入口：`/profiles/{profileId}`。

测试数据：同一疾病档案下至少 3 条不同日期记录，其中 2 条属于同一批次。

期望结果：时间线倒序；批次详情展示相关记录和生成输出；导航返回后仍在同一档案上下文。

截图/日志证据：时间线截图、批次详情截图、导航前后 URL 或状态记录。

## Agent 评估指令

Agent 必须检查排序测试和手工批次详情证据。没有多记录样本时不得判定 `PASS`。

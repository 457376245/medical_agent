# 交付上线评估标准-总览

## 评估结论规则

| 结论 | 判定规则 |
|------|----------|
| PASS | 所有业务评估文档的 P0/P1 项均有证据通过，且通用发布门禁通过。 |
| CONDITIONAL | P0 项通过，P1 项存在已记录限制、灰度策略或明确负责人。 |
| FAIL | 任一 P0 项失败、缺少证据，或通用发布门禁未通过。 |

状态枚举：`TODO`、`待验证`、`通过`、`失败`、`不适用`。没有证据时必须写 `待验证`，不能写 `通过`。

## 自动化测试

建议命令：

```powershell
rg -n "TODO|待验证|FAIL|CONDITIONAL|PASS" docs/release
```

通过标准：能定位所有待补证据和结论状态；没有将缺少证据的项目标为 `通过`。

失败处理：补充证据路径，或将上线结论降级为 `CONDITIONAL` / `FAIL`。

## 手工验收

操作入口：`docs/release/`。

测试数据：本目录所有业务评估文档。

期望结果：测试人员能按业务域逐份执行；Agent 能按总览索引找到对应文档。

截图/日志证据：评估记录、测试执行记录、发布审批记录。

## Agent 评估指令

Agent 必须先读取本总览，再读取对应业务评估文档。只能基于代码、测试输出、手工记录、审核记录和发布记录给出结论。文档中写“已完成”不等于已通过验收。

输出格式必须包含：`结论`、`阻断项`、`缺失证据`、`建议下一步`。

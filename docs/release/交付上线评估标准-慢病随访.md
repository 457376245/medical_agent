# 交付上线评估标准-慢病随访

## 评估结论规则

| 结论 | 判定规则 |
|------|----------|
| PASS | 慢病画像、任务、症状、风险概览、证据引用、Agent 上下文、前端驾驶舱均有证据通过。 |
| CONDITIONAL | 主链路可用，但风险分层或部分证据来源仍需限制说明。 |
| FAIL | 风险概览与文档承诺不一致，或任务/症状/画像任一主链路不可用。 |

## 业务范围

范围内：慢病画像、随访任务、症状/体征记录、风险概览、证据引用、Agent 慢病上下文、前端慢病驾驶舱。

范围外：疾病特异规则引擎、自动提醒调度、医学知识 RAG、多角色专业版。

## 自动化测试

建议命令：

```powershell
mvn "-Dtest=PatientCareControllerTest,AgentContextControllerTest" test
uv run pytest tests/test_agent/test_context_guidance.py tests/test_prompts/test_system_prompt.py tests/test_prompts/test_templates.py
npm test -- --run src/components/agent/agent-utils.test.ts
npx tsc --noEmit
```

通过标准：Java、Python、前端测试通过；风险概览 service 级测试需补齐后才能判定 `PASS`。

失败处理：风险概览输入不完整标记 `FAIL`；前端类型检查因依赖未同步失败时，记录环境和重跑证据。

## 手工验收

操作入口：`/agent`。

测试数据：有疾病档案、至少 1 份报告、慢病画像、逾期任务、`WARNING` 症状记录、红旗备注。

期望结果：驾驶舱展示画像、风险、任务、症状；风险随任务/症状变化；Agent 对话 metadata 携带 workflow、audience、urgency；回答区分事实、解释和建议动作。

截图/日志证据：驾驶舱截图、风险 API 响应、Agent metadata、对话样例、测试输出。

## Agent 评估指令

Agent 必须重点检查风险概览是否实际消费 `abnormalBaseline` 和 `doctorInstructions`。如果只能看到字段保存和回传，不能看到风险或证据使用，结论必须为 `FAIL` 或 `CONDITIONAL`，不能为 `PASS`。

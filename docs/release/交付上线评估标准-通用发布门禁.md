# 交付上线评估标准-通用发布门禁

## 评估结论规则

| 结论 | 判定规则 |
|------|----------|
| PASS | OpenAPI/AsyncAPI、兼容性、安全、性能、回滚、环境和 on-call 均有证据通过。 |
| CONDITIONAL | 非 P0 项存在限制，但有灰度方案、负责人和回滚路径。 |
| FAIL | 任一 P0 门禁失败或缺少证据。 |

## 业务范围

范围内：所有业务发布前的工程、质量、安全和运维门禁。

范围外：单个业务功能验收；业务验收由对应业务评估文档完成。

## 自动化测试

建议命令：

```powershell
mvn test
uv run pytest
npm test
npx tsc --noEmit
pytest tests/contract
pytest tests/integration
```

通过标准：命令在约定环境通过；如有跳过，必须记录原因、影响和负责人。

失败处理：P0 命令失败标记 `FAIL`；环境问题必须补环境证据后重跑。

## 手工验收

操作入口：发布审批记录、CI 输出、接口 diff、测试报告。

测试数据：本次发布涉及的所有业务域。

期望结果：业务评估文档均完成；通用门禁均有证据；回滚和 on-call 可执行。

截图/日志证据：CI 链接、命令输出、接口 diff、发布审批、回滚记录。

## Agent 评估指令

Agent 必须把本文件作为最终上线判定入口。即使业务文档均通过，只要通用发布门禁 P0 缺证据，最终结论必须为 `FAIL`。

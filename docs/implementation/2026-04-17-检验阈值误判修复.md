# 检验阈值误判端到端修复

## 元数据

- 状态：进行中（多段参考范围跟进修复）
- 负责人：Codex

- 相关请求：修复“检测下限/检测上限/最低检测量”等非标准参考范围被误判为正常的问题，覆盖记录详情、趋势图和报告分析链路；继续修复“适宜<4.10；增高4.10-4.90；很高>4.90”这类多段参考范围被误判为正常的问题。

## 摘要

- 当前系统对结构化检验字段的异常判定过度依赖自由文本参考范围和前端简化解析，已修复“最低检测量 50IU/mL”配合“>1.00×10^8 IU/ml”这类阈值型误判；但跟进确认发现“适宜<4.10；增高4.10-4.90；很高>4.90”这类多段带标签参考范围，仍会把异常段误识别为正常区间。本次跟进修复继续采用“Java 读取时增强 + 前端优先消费增强结果”的方式，在不改表结构、不回灌历史数据的前提下修正多段参考范围语义。

## 背景和目标

- 业务背景：医疗报告中的参考范围不总是标准区间，经常出现检测下限、检测上限、线性范围、未检出阈值等方法学描述。
- 用户/问题陈述：当结果值与阈值描述一起出现时，系统会把明显异常的指标显示为正常，进而影响趋势筛选和报告分析文案。
- 成功标准：
  - 详情页结构化字段不再把阈值型参考范围显示为正常
  - 详情页结构化字段不再把“适宜/正常/目标 + 偏高/偏低/很高”等多段参考范围中的异常段显示为正常
  - 趋势图能把阈值型异常纳入异常项集合
  - 趋势图和历史 payload fallback 对多段参考范围判定一致
  - 报告分析文案不会把 `resultState=threshold` 的字段描述为正常
  - 历史 `structured_results` 数据无需重跑解析，也能在读取时补出一致的判定元数据

## 范围

- 范围内：在 `backend-java` 增加字段解释器，并在记录详情、趋势接口、报告分析上下文读取路径中统一补充判定元数据
- 范围内：扩展详情字段和趋势字段返回体，增加 `numericValue`、`comparisonType`、`resultState`、参考边界信息
- 范围内：在 `frontend` 抽共享消费逻辑，优先使用后端增强字段，缺失时再走兼容回退
- 范围内：补齐多段参考范围的标签解析，按“正常段/偏高段/偏低段”解释结果状态
- 范围内：调整 `backend-agent` 的 parse / report analysis 提示词，强调原文保真和阈值异常关注
- 范围内：补充覆盖阈值型参考范围和科学计数法结果的针对性测试

## 实施计划

1. 在 `backend-java` 设计并实现字段解释器，支持科学计数法、比较符、单侧边界、阈值关键词识别。
2. 在详情、趋势、分析上下文读取时统一增强字段 payload，并扩展趋势 DTO。
3. 在 `frontend` 抽共享消费逻辑，优先使用增强字段，兼容旧 payload 回退计算，并新增 `threshold` 展示态。
4. 在 `backend-agent` 强化 parse / generate 提示词，保证比较符与科学计数法不被改写，并把阈值异常作为需关注项。
5. 补充三端针对性测试，验证高值阈值、普通区间、历史数据兼容路径。
6. 跟进修复多段带标签参考范围，保证 `适宜<...; 增高...; 很高...` 这类表达按正常基线或异常标签正确判定。
